# Refactor plan

## Why
Four files carry most of the risk: `chromasmith-22.html` (32k lines, 21 `<script>` blocks, ~1,300 top-level functions, 17.7MB), `desktop/library-ui.js` (17.4k lines), `desktop/src-tauri/src/catalog.rs` (14.4k lines, 25 commands) and `library.rs` / `main.rs` (4.9k / 4.2k). Single-file size makes edits slow, reviews hard, and the shader/template-literal bug class easy to hit.

## Constraints (do not break)
- The web app must stay single-file/offline at deploy time. Split in source, **concatenate at build** (extend `build-ios.sh`/a new `tools/scripts/build-app.mjs`), or keep native ES modules only where the Tauri/Pages loaders allow.
- Pixel worker is built via `toString` of real functions; extracted code must stay toString-safe (no closed-over module state).
- Export output must stay bit-identical: `test/golden/` is the oracle.
- Design tokens remain generated between `TOKENS:` markers.

## Principles
1. Behaviour-preserving moves only; no fixes mixed in. One module per commit.
2. Every step gated by the existing suite, run once per phase in background (`npm test`, plus `export_harness` after any shader-adjacent move).
3. Extract leaf modules first (no dependents), core last.
4. Commit and push after each step.

## Phases

### Phase 0 — Baseline and map (no code moves)
- Generate a machine-made inventory: per-script-block line ranges, top-level function list, global-variable reads/writes per function, cross-block call graph (script: `tools/scripts/app-map.mjs`, output to `docs/plans/app-map.json`).
- Record baselines: `npm test`, golden render hash, `perf:test`, gzip size.
- Done when: map exists and is regenerated by one command; baselines recorded green.

### Phase 1 — Web app: source split with a concat build
- Introduce `src/app/` with the 21 script blocks as files in their current order (pure cut/paste, zero edits), plus `src/app/shell.html` for markup/CSS.
- Build step reassembles `chromasmith-22.html`; the output must be byte-identical to today's file (verify by diff). Pre-commit hook rebuilds and checks.
- Decide the source of truth: `src/` edited, `chromasmith-22.html` generated (update CLAUDE.md, hooks that grep the big file, BUILD-bump hook).
- Done when: build reproduces the file exactly; all gates green.

### Phase 2 — Web app: carve domains out of the big script
Order (leaf → core), each its own file under `src/app/`:
1. Vendored decoders/inlined libs (pako, utif2) → `vendor/` loaded by the build.
2. LUT data/loading (`LUT_PRESETS`, `LUT_META`, lutcache).
3. Colour utils (Oklab, curves, DCP bake) — pure functions, add unit tests.
4. RAW/TIFF/video I/O.
5. Masks (raster storage, AI masks, skin tone).
6. UI panels (Swiss v2 blocks already separate; fold their duplicated DOM helpers).
7. `FXR` renderer + shaders last, split into one file per GLSL program; keep the backtick/`${` lint as a build check.
- Replace implicit globals with a single namespace object per domain, migrated incrementally behind aliases.
- Done when: the main script has no domain function left that has a file of its own; golden renders unchanged.

### Phase 3 — `desktop/library-ui.js`
- Same recipe: scan top-level sections, split into files (state, grid/virtualisation, filters, jobs/notifications, backup/relink, DS block), concat or ES-module build into `desktop/dist/`.
- `npm run editor:gates` already rebuilds `desktop/dist/`; hook the split into that.
- Done when: `ui:test`, `library:*`, Playwright pass; `perf:test` library budgets unchanged.

### Phase 4 — Rust backend
- `catalog.rs` (14.4k): split into a `catalog/` module — schema/migrations, queries, indexing, thumbnails/previews, ratings/metadata, commands (thin Tauri wrappers). Keep public API via re-exports so callers don't change.
- `main.rs`: move the 15 commands and setup into `commands/` and `setup.rs`; leave `main.rs` as wiring.
- `library.rs`: separate FS scanning, relink, and commands.
- Per Cargo build discipline: background builds; verify with 3+ real launches against the real large library (boot-sequence lesson).
- Done when: no file over ~2.5k lines, `cargo test` green, real-library launches clean, diagnostics CLI shows no new stalls.

### Phase 5 — Tests and tooling
- Dedupe the wireframe/editor test helpers (`wireframe_checks_lib.mjs`), and move the 100+ `package.json` scripts into grouped runners.
- Add a CI check that fails if any source file exceeds the size ceiling or `chromasmith-22.html` differs from a fresh build.

## Completeness check
Completeness is defined by scans of the running repo, not this list:
- Web app: Phase 0 map lists every top-level function and global; Phase 2 is done only when a re-run of the map shows each function assigned to exactly one module file and no function left unassigned.
- Library UI: same scan on `desktop/library-ui.js`.
- Rust: `grep '#\[tauri::command\]'` count before == after, and every command appears in the `invoke_handler` list; `wc -l` ceiling check on every `src/*.rs`.
- Surfaces: run `ui:test`, `editor:gates` and Playwright in light and dark themes and at every width the audit covers, including all resizer min/default/max states, to catch layout regressions from load-order changes.
- Render parity: `export_harness` (every fixture × recipe) and `video_harness` identical to goldens.
- Gap review: after each phase, a fresh-context reviewer diffs the map against the repo and lists anything unassigned.

## Risks
- Load-order changes in the concat build (hoisting, `const` TDZ) — mitigated by preserving order in Phase 1 and byte-identical output.
- `toString` worker builds breaking on moved code — covered by export parity.
- Concurrent sessions touching the same files — do each module move in a single commit and push immediately.
- Flaky gates (`export_harness` blank render, `video_harness`) — rerun before blaming the refactor (see docs/testing.md).

## Agent-ergonomics follow-up (2026-10-16)
Decision: skip a full ES-module rewrite (little user benefit, high silent-breakage risk). Instead:
- `tools/scripts/app-uses.mjs <name> [--lines] [--all]` — definitions + callers by file, so an agent sees blast radius before editing.
- `test/unit/` (`npm run unit:test`, in `npm test`) — no-browser tests for OKLab/OKLCH and ProPhoto->sRGB, using `extract.mjs` to lift functions out of the app. Add more pure helpers the same way; masks already have `npm run mask:test`.
- Only consider real modules for color/RAW maths and masks, and only if these tests make it cheap.

### Domain layout fix (2026-10-16)
Sections were first filed by header text, which misplaced mixed runs (e.g. shader code under a Google Photos comment). Now: sections over 450 lines are cut further at column-0 declarations outside template literals (`cont-<identifier>` parts), and each part is filed by the first identifier it declares, then by header. Folders: renderer, color-raw, masks, subjects-ai, collage, google-photos, export-io, history-presets, shell-ui, editor (catch-all). 146 parts in `src/app`.
